## 완료 상태 문구

### ANAGENT 반복 오탐 개선

Infrabot 기반 SSH/SFTP 자동화 과정에서 발생한 `sshd`·`sftp-server` 반복 탐지를 자산, Agent UUID, 파일 해시·경로 및 IP Connect 이력으로 검증했습니다. 예외 대상 자산에 `anagent` 태그를 부여하고 파일 해시 조건을 결합한 제한적 예외처리를 적용했습니다. 동일 7일 비교 결과 주요 반복 탐지는 1,094건에서 663건으로 431건, 약 39.4% 감소했습니다. 예외 대상 Agent의 22222 포트에 허용되지 않은 Source IP가 접근하는 경우를 탐지하는 STAR Custom Rule도 운영 반영했습니다.

### 서버 EDR 탐지 테스트

Linux·Windows 악성 명령어 탐지 테스트에서 일부 Alert가 발생하지 않은 원인을 Event Search의 Process Creation 로그와 Behavioral Indicator, SentinelOne KB 기준으로 검토했습니다. 명령어 실행 자체가 아니라 프로세스 관계와 파일·네트워크 후속 행위가 Alert 생성 조건에 영향을 주는 것을 확인했고, 로그 수집·Indicator·Threat Alert 승격을 구분해 고객사에 안내했습니다.

## 진행 상태 문구

- 솔루션 담당 부서에 태그·파일 해시 기반 예외 기능 테스트를 요청하고 재현 결과를 대기 중입니다.
- 고객사 테스트 결과와 KB의 Alert 생성 조건을 추가 대조 중입니다.
- Custom Rule 적용 후 동일 조건의 정상·비정상 접근 로그를 비교해 탐지 범위를 확인 중입니다.

## 대기 상태 문구

- 고객사에서 제공한 테스트 명령어, 실행 경로와 대상 Agent 정보를 추가 확인해야 합니다.
- 정책 적용 범위와 Rule 우선순위는 솔루션 담당 부서의 최종 확인 후 확정합니다.
- 원본 증적의 기간·집계 기준을 재확인한 뒤 보고서 수치로 확정합니다.

## 보고서 작성 시 주의사항

- 쉴더스의 1차 Resolve 처리와 본인이 수행한 Event Search 재검증을 구분한다.
- 오탐 사유는 “정상 업무”라고만 쓰지 말고 프로세스·파일·IP Connect 근거를 적는다.
- Alert 건수는 기간과 필터 범위를 함께 적는다.
- 예외처리와 보완 Rule을 한 세트로 기록한다.

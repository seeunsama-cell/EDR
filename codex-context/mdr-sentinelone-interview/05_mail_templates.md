# Mail Templates

## 고객사 ANAGENT 분석 결과 회신

제목: ANAGENT 반복 탐지 분석 및 예외처리 방안 안내

안녕하세요.

요청하신 ANAGENT 관련 반복 탐지를 자산, Agent UUID, 파일 해시·경로와 IP Connect 이력 기준으로 확인했습니다. 해당 이벤트는 Infrabot 기반 SSH/SFTP 자동화 과정에서 발생한 정상 작업과 일치하는 것으로 확인했습니다.

다만 동일 프로세스와 파일이 비정상 접속에도 악용될 수 있어 단순 프로세스 예외는 적용하지 않았습니다. 예외 대상 자산에는 `anagent` 태그를 부여하고 승인된 파일 해시가 함께 일치하는 경우에만 예외가 적용되도록 범위를 제한하는 방안을 제안드립니다.

추가로 예외 대상 Agent의 22222 포트로 허용 목록에 없는 Source IP가 접근하는 경우를 탐지하는 Custom Rule을 적용해 예외로 인한 보안 공백을 보완하고자 합니다.

## 내부 기능 검토 요청

제목: 태그 및 파일 해시 기반 예외처리 기능 검증 요청

고객사에서 특정 자산에 한정한 예외처리를 요청했습니다. 현재 개별 자산을 직접 지정하기 어려워 예외 대상 Agent에 식별 태그를 부여하고, 태그와 파일 해시가 동시에 일치할 때만 예외가 적용되는 구성을 검토하고 있습니다.

해당 기능의 적용 가능 여부와 정책 우선순위, 기존 탐지 영향, 롤백 방법을 테스트해 주시기 바랍니다. 테스트 결과와 재현 조건을 정리해 고객사에 안내하겠습니다.

## 서버 EDR 탐지 테스트 분석 회신

제목: 서버 EDR 악성 명령어 탐지 테스트 결과 및 미탐 원인

고객사의 Linux·Windows 테스트 결과와 Event Search의 Process Creation 로그 및 Behavioral Indicator를 대조했습니다. SentinelOne은 특정 명령어 실행 자체를 일괄 탐지하는 방식이 아니라 프로세스 실행 관계, 파일 접근·생성, 네트워크 연결 등 후속 행위와 정책 조건에 따라 Alert를 생성합니다.

따라서 일부 테스트에서 Alert가 발생하지 않은 것은 로그 수집 실패나 제품 장애라기보다 해당 테스트 행위가 기본 Alert 생성 조건을 충족하지 않은 결과로 판단됩니다. 원본 이벤트 수집, Indicator 생성, 최종 Alert 승격 여부를 구분해 확인했으며 KB 기준과 솔루션 담당 엔지니어의 검토 결과도 분석 방향과 일치했습니다.

## 특정 스코프·태그 예외 문의 대응

고객사 문의 내용을 KB와 정책 범위 기준으로 확인한 결과, 자산별 직접 예외가 어려운 제약이 있음을 확인했습니다. 이에 대상 자산을 태그로 분류하고 파일 해시 등 추가 조건을 결합하는 방안을 제안했습니다. 적용 전후 동일 기간의 Alert 추이를 비교하고, 예외 대상 밖의 비정상 Source IP 접근은 별도 Custom Rule로 탐지하도록 보완했습니다.
